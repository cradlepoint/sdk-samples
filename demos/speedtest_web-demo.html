Speedtest Web

"The internet is slow at that site." Is it the link? Speedtest Web has the router test its own WAN on a schedule and writes every result into NetCloud Manager, so the link's real speed shows up next to the device with nobody on site.

Results land in NetCloud Manager

Each good result becomes one line (speeds, latency, carrier, time) in Asset ID, Description, or SDK Data.

Runs on a schedule

Cron presets from every 5 minutes to weekly. The schedule resumes on its own after a reboot.

Any SIM, three enginesbonus

Test the backup SIM without failing over. Built-in netperf, bundled iPerf3, or your own Ookla binary.

How it works

Writes only good results

After each successful test, one line goes to every output you enable: Asset ID, Description, SDK Data, or a custom path. For example DL:96.82Mbps UL:46.74Mbps Lat:12.5ms Jit:2.1ms Iface:Carrier B Engine:netperf 2026-06-13T11:30:00Z. A test that returns zero for both download and upload is logged as failed and is not written, so NetCloud Manager keeps the last good line and its timestamp.

Schedules with cron, in UTC

Pick a preset (every 5 minutes up to weekly), use the visual builder, or type a cron expression. The scheduler checks every 15 seconds against the router's UTC clock and skips a slot if a test is already running. The schedule is saved to SDK appdata and resumes after a reboot.

Binds the test to one WAN

The interface list shows connected WANs sorted by priority, with carrier and SIM names. The test is pinned to the one you pick (netperf ifc_wan, iPerf3 -B, Ookla -I), so a standby link gets measured without touching WAN priority.

Three engines

Netperf is built into the router: download, upload, and optional TCP_RR latency/jitter. iPerf3 uses the bundled binary and your server, retrying the next port in a range like 5201-5210. Ookla appears when you add a licensed binary and streams live speeds. History keeps the last 100 tests, with CSV and HTML reports.

See it in the app

SDK Data settings

All optional. The web UI writes these for you, and because they live in SDK Data, you can also push them from a NetCloud Manager group.

SettingRequiredDefaultWhat it does
speedtest_web_web_port No First free port from 8000, then saved Web UI port (1024 to 65535). Set it to pin the port; delete it and restart to pick one automatically again.
speedtest_schedule No None (schedule off) The saved schedule as JSON.
  • enabled — run on the schedule (default false)
  • autostart — turn the schedule on at boot (default false)
  • cron — minute, hour, day of month, month, day of week, in UTC
  • engine and params — the engine (default netperf) and the test settings to repeat
speedtest_outputs No None (results stay in history) JSON array of where each good result is written: config/system/desc, config/system/asset_id, appdata:speedtest_results, or a custom path.
netperf_servers No None (the router's default server) JSON array of saved netperf servers, each {"server", "label"}.
iperf3_servers No None JSON array of saved iPerf3 servers, each {"server", "port", "city", "country"}. A port range like 5201-5210 retries the next port when one is busy.
  • Set fields in Ericsson NetCloud Manager under the device or group's SDK Data. The web port and schedule are read at startup, so restart the app after changing them.
  • With the SDK Data output on, the app writes each result to speedtest_results. That's an output, not a setting.
  • Open the web UI at http://router_ip:<port>. The port is in the app log at startup.
  • LAN access to the web port needs a zone firewall forward from the Primary LAN Zone to the Router Zone.
  • Needs NCOS 7.25 or later. Ookla needs your own licensed ARM64 binary in the app folder; iPerf3 needs a server you provide.
