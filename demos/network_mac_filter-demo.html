Network MAC filter

Cap how many unknown devices can join each network on an Ericsson Cradlepoint router. Known vendors always get in, the first unknowns up to your limit are let in, and the rest are blocked automatically with firewall deny rules.

A limit per network

Set a maximum number of unknown devices for each LAN. Zero means no limit. Devices from allowed MAC prefixes never count toward it.

Blocked by firewall rule

An over-limit device gets a deny rule named Deny- plus its MAC in the zone firewall policy for that network.

Control it from a web page

A web UI shows every device as allowed, over limit, or blocked. You can also block and allow by hand.

Control it without the web page

The app also has control paths for scripts. Each takes the network name with spaces and slashes replaced by underscores.

  • control/network_mac_filter/{network_name}/block and unblock take a MAC address.
  • add_known_prefix and remove_known_prefix take one or more prefixes, comma separated.
  • clear_sticky with the value 1 frees the learned slots for that network.

Per-network status is published to status/network_mac_filter/{network_name}.

How it decides

Each cycle classifies every device on the ARP table, then adds or removes deny rules.

Known prefixes

A MAC that starts with an allowed prefix is known. It is always allowed and does not count toward the limit.

Sticky slots

An unknown MAC that gets a free slot holds it while the app runs. A reboot, or the clear_sticky action, frees them.

Over limit and blocked

Over limit is automatic and ends when a slot is freed. Blocked is manual and lasts until you allow the device.

Grace period

A known-prefix device must be missing for 6 seconds before it is dropped from tracking. Sticky and blocked devices are never dropped automatically.

Setup notes

This app has no SDK Data fields to set.

  • Create a zone firewall filter policy for each LAN you want to control. The policy name must match the LAN name exactly, and its default action should be allow. Without it the web page shows a warning and disables Block and Allow.
  • Apply the filter policy where the network forwards to another zone (for example LAN to WAN).
  • Web UI at http://router_ip:<port>; the port is in the app log (usually 8000). LAN clients need firewall zone forwarding from the Primary LAN Zone to the Router Zone to reach it.
  • Setting network_mac_filter_web_port or disable_ui in Ericsson NetCloud Manager SDK Data: a port change needs an app restart; disable_ui does not.
