Splunk conntrack

Send every new network connection through an Ericsson Cradlepoint router to Splunk as a readable event. The app checks the connection table every 5 seconds and forwards each connection once, using Splunk's HTTP Event Collector.

One event per new connection

Each event shows the source and destination address and port, the protocol, and the status, tagged with the router.

Router identity on every line

Events start with the router name, MAC address, serial number, and firmware version, so you can tell routers apart.

Two fields to set

Add a Splunk URL and a HEC token in SDK Data. Until both exist, the app waits and checks again every 60 seconds.

How it works

Poll, compare with what was already sent, and post only what is new.

Settings first

It reads splunk_url and splunk_token every pass. If either is missing it logs that and sleeps 60 seconds.

Read the table

Every 5 seconds it reads the firewall connection table and notes each connection ID.

Send only new IDs

An ID not seen before is posted to Splunk, then remembered. IDs no longer in the table are dropped from memory.

Plain text event

Each event is one string in the form "router identity, connection ID, source:port -> destination:port, proto, status".

See it in the app

SDK Data settings

Both fields are required. The URL is your Splunk HTTP Event Collector endpoint.

SettingRequiredDefaultWhat it does
splunk_urlYesNot setSplunk HEC endpoint, for example https://your-splunk-instance.splunkcloud.com:8088/services/collector. Read on every pass.
splunk_tokenYesNot setYour Splunk HEC token. Read on every pass.
  • Set both in Ericsson NetCloud Manager under the device or group's SDK Data (on the router, System > SDK Data). They are read every pass, so no restart is needed.
  • The app has no web page and no port to open. Status and errors appear in the router log.
  • The router needs a route to your Splunk instance. The app posts to the URL as given and does not verify its TLS certificate.
  • Needs firmware 7.26 or later.
