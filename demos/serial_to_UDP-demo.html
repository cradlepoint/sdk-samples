Serial to UDP

Send everything that arrives on a router's serial port to up to 32 UDP destinations. An Ericsson Cradlepoint router reads the serial device and forwards each chunk, and you set it all up on a web page.

Fan out to many hosts

Each chunk read from the serial port is sent as its own datagram to every destination. An unreachable one is logged and skipped.

Everything on one web page

Set destinations and the UDP source, and edit serial port settings, with no restart. The app rebinds and reopens by itself.

Recovers on its own

If the serial port or socket fails, the app reconnects. With no destinations it keeps draining the port so the buffer does not back up.

How it works

A read loop on the serial port, a UDP socket, and a web page that edits both.

UDP settings in SDK Data

Destinations and source address are stored in one SDK Data field. Serial settings live in the router's own serial config.

Defaults in code

The source defaults to the router's primary LAN address on port 5000. Blank source fields use those defaults, and they are never written to SDK Data.

Live changes

Saving a page rebinds the socket or reopens the serial port on its own.

No login on the web page

Anyone who can reach the page can change destinations and serial settings. Keep it to trusted networks.

See it in the app

SDK Data settings

Add at least one destination, or no data is forwarded. Most people do this on the web page, which writes the same field.

  • Open the web page at http://router_ip:<port>. The port is in the app log, usually 8000. If the port is invalid or stays busy, the web page does not start but forwarding keeps running.
  • For LAN clients to reach the web page, the firewall needs zone forwarding from the Primary LAN Zone to the Router Zone.
  • To change the web port, set serial_to_UDP_web_port in Ericsson NetCloud Manager SDK Data and restart the app.
  • Prerequisite: a serial device on the router (for example ttyUSB0 or ttyACM0) and network access to each destination. Needs firmware 7.26 or later.
